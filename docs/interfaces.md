# Interfaces and data boundaries

## 0.2 intelligent-system contracts

Three layers stay separate: native-conversation Builder, ordinary target architecture and optional intelligence. Target business data does not use the construction journal.

ArchitecturePlan describes components/interfaces/dependencies/launch/acceptance; IntelligenceProfile describes modes/models/resources/context/permissions/budgets; ExplorationRecord describes questions/strategies/candidates/evidence/decisions. Record/query with `awb architecture`, `awb profile`, `awb explore`; replacement uses `--file --id --expected-revision`. `explore --action next|answer|reopen` supports ongoing grill. `profile --discover CODEX_HOME` inventories metadata only; `profile --compile --id ID` checks approval. Legacy missing fields stay unknown.

`verify_candidate` supports registered program/service/artifact/domain verifiers. Architecture-linked acceptance requires the declared acceptance_id and exact config. `register_verifier(name, version, callable, dependency_paths)` binds verifier code; callbacks return actual checks/artifacts/dependency hashes. Goal/candidate/criteria/architecture/profile/version bind evidence. `delivery` checks whole-goal coverage, manifest files and actual launch evidence. Custom startup/domain checks are explicit verifier extensions.

`AppServerClient` owns local stdio, initialization, start/resume, turn/start/interrupt, events and explicit user approvals. Targets own UI/business sessions. Exec produces structured results and denies unresolved approvals. Both inherit provider configuration/rules; workspace writes need authorization. No automatic installation or key provisioning. [Official app-server](https://learn.chatgpt.com/docs/app-server), [noninteractive mode](https://learn.chatgpt.com/docs/non-interactive-mode).

## Retained foundations



All JSON records have schema version 1. Goal revision increments by exactly one under the same goal ID. Requirements have stable IDs, text, kind, source and confirmation status. The CLI `goal` command replaces a goal using an expected revision; the previous JSON is retained and hashed in SQLite. Future incompatible versions are rejected rather than guessed.

`awb_core.state.Store` provides initialization, optimistic record updates, legal cycle transitions, evidence validation and goal/input/action-bound reviews. `record_transition(id, expected_revision, transition, evidence_refs)` owns cycle status changes. A cycle has evaluating, awaiting_approval, implementing, verifying, deciding, accepted, rolled_back, needs_human and cancelled states; completed target runs have separate status. Completion does not itself move a cycle to accepted.

`prepare_change(accepted_spec, candidate_spec, store)` accepts an accepted path-to-hash map and a candidate path-to-text/null map. Call `Store.accepted_spec()` for the authoritative baseline. Candidates bind its revision; acceptance commits the next specification and the cycle in one transaction, then publishes recoverable JSON views. `apply_change` reconciles its journal against actual files. `rollback_change` restores known prior bytes and rejects third-party drift; accepted changes require a new compensating candidate. `verify_candidate({store, cycle_id, change_id}, acceptance)` executes the materials domain verifier; acceptance has kind, run_id and an independent reference mapping. Evidence snapshots must match the verifier's observed hashes, and changed Python candidates must be present in the recorded run dependencies. `apply_decision` requires current evidence for acceptance. Other domains may call the runtime and add their own deterministic verification through the Python evidence API; 0.2 CLI supports the registered verification kinds described above.

`execute_node(node, task, context, Budget(max_calls, max_seconds))` returns schema_version, attempt_id, node_id, backend, status, verification, result, usage, logs and elapsed_seconds. Verification starts unverified. Context supplies workspace, offline policy and an optional cancellation signal. A command node declares `argv`, `trusted: true`, `allowed_executables`, timeout and output_schema. Codex and Ollama declare explicit model names; output_schema is supplied by a consuming workflow or explicitly for general graph use. Cost is null when unavailable.

Graph JSON has a `nodes` array. Each node declares a unique id, backend contract, `after` dependencies and optional `when: {node, key, equals}`, `repeat` (1–10), `input_files` and `side_effect` (none, idempotent or unknown). An idempotent contract requires an explicit `idempotency_key`; automatic retry and replay are limited to that contract or side_effect none. Use input_files for scripts and data whose content affects reuse; command file arguments and readable executables are also hashed. Include the interpreter/model version in approved configuration and re-probe on change. Each node has isolated output storage. Any attempted uncertain side effect, including failed or timed-out attempts, requires human reconciliation. Calls and cumulative execution seconds are reserved before submission; completed attempts refund unused time, while crashes retain the reservation. Successful parallel siblings persist even when another worker raises. A project mutation lock coordinates generation, execution, goal changes and exports.

`plan_from_selection({steps: [{id, after}]}, catalog)` only permits selections from an approved node catalog; it cannot add executable text or change permissions. The planner itself may be a model node returning this JSON, followed by deterministic plan validation. The core has no requirement for a planning Agent or external workflow framework.

Commands run with the current operating-system authority; neither directory checks nor argv establish a sandbox. The runtime declines strict isolation requests. Generic command nodes are disabled for an offline goal. Local HTTP policy and provider credential handling must be verified in the actual deployment. CSV exports prefix formula-like strings with an apostrophe for safe spreadsheet viewing; JSONL retains the exact source text.

# Exploration records and resource discovery

Use environment inspection for discoverable facts; primary-source documentation/repositories for version-specific capabilities; a bounded prototype for uncertain behavior; comparison for competing architectures. Weigh expected uncertainty reduction and decision impact against time/calls, privacy and reversibility. Do not repeatedly ask facts that tools can safely reveal. A user preference or permission still needs the user's answer.

`awb explore --file RECORD.json --project PROJECT` records an ExplorationRecord. Query/list with `--id ID` or no file. `--action next` ranks unresolved questions; `--action answer --id ID --file ANSWER.json --source user|environment|experiment` preserves an attributable choice/reason; `--action reopen --id ID --reason REASON` keeps old history. Answers refer to observed candidate IDs. Reopened questions are unresolved even when the old answer exists; goal changes reopen exploration and stale architecture/profile contracts.

Question fields: stable id/text, impact, uncertainty [0,1], discoverable, consequential and optional reversibility. Record search strategy/method/reason; open/selected/rejected candidates with evidence and rejection reasons; observations with source and optional digest; decision choice/reason/reopen triggers. The host performs actual research and semantic judgment. The helper does not infer requirements from arbitrary natural language or execute a model-proposed search command.

Inventory project/global Skills and installed plugins with `profile --discover CODEX_HOME`; inspect host-exposed tools/MCP separately in native Codex. Inventory means presence, not compatibility or a license grant. Check actual source/revision, license/terms, instructions, dependencies, host APIs and a scoped compatibility probe before enabling. Prefer project-scoped configuration; preserve the current provider and applicable host/project rules. New installation, credentials, fees and destinations enter a consequential contract review. Do not copy credentials into records, prompts, repository or bundles.

The design space stays open. The legacy graph catalog restricts authorized graph execution only; it cannot forbid a different modern program architecture. Failed experiments, unreachable backends and resource/budget limits must change the next route or create a concrete wait/decision checkpoint.

# Complete construction loop

Keep the original request and active requirements, not a convenient sample, as the completion scope. Native Codex hosts the Builder. Its target application chooses its own architecture, business state and optional intelligence.

Evaluate the gap and highest-impact uncertainty → create an authorized bounded candidate/prototype → run independent actual checks → decide accept/revise/replace/rollback/wait/cancel with reasons and refuting evidence. Local acceptance advances one part; compare whole-goal requirement coverage and keep constructing remaining parts. Reopen affected decisions on evidence or goal changes. A changed acceptance rule is versioned, not silently tuned to the current output.

Persist goal, architecture/profile/exploration, cycle/change/evidence and decisions in the existing Store. Target business state is separate, linked by actual identifiers and artifacts. Existing projects lacking new records have unknown architecture/profile; inspect before proposing them. Keep source-file ownership, drift checks, history and compensating rollback.

Adaptive grill is continuous: use saved answers, inspect discoverable facts, then ask the next consequential question. Ordinary reversible details proceed within the agreed scope. New installations, credentials, cost, data destinations or fundamental acceptance/architecture changes require a real decision. Neither a tool result nor a generated profile grants authority.

Deliver a target entrypoint usable after this conversation, dependencies/configuration, architecture explanation, actual requirement-linked acceptance, recovery and extension instructions. `delivery` reports missing/invalid evidence and unconfirmed requirements; it does not invent human acceptance. Budget exhaustion or inaccessible inference saves a checkpoint and records the blocker, without hidden extra attempts.
